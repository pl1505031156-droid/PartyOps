# 党建智办 PartyOps 1.4.2 安装、升级与回滚

最后核验日期：2026-08-09（Asia/Hong_Kong）

## 版本与兼容范围

- 程序版本：`1.4.2`；数据库模式：`0017`。
- 数据库迁移与 1.3.4 正式版、1.4.0/1.4.1 候选数据兼容。
- Windows 10/11 x64、UOS V20 amd64/arm64 为目标平台；当前仅完成 Windows 11 x64 源码与浏览器候选验证，正式安装制品仍受发布门禁阻断。
- 1.4.2 新增 Firecrawl WASM 文档阅读能力，不新增数据库迁移。

## 升级前

1. 在“管理 → 备份恢复”创建并下载完整备份，校验备份清单和 SHA-256。
2. 记录主机/协同机角色、主机地址、设备批准状态和共享目录数量。
3. 确认磁盘有足够空间同时容纳当前程序、升级包、数据库快照和回滚副本。
4. 只使用对应 GitHub Release 中带 SHA-256、签名和验收记录的正式制品。
5. 先升级主机，健康检查通过后再升级协同机；不要让不同协议版本长期混跑。

## Windows 首次安装

```powershell
Get-FileHash .\PartyOps_1.4.2_windows_amd64.exe -Algorithm SHA256
Get-AuthenticodeSignature .\PartyOps_1.4.2_windows_amd64.exe
```

签名与 Release 清单一致后，以管理员身份运行安装器。主机数据位于 `%PROGRAMDATA%\PartyOps`；协同机配置和接收目录位于 `%LOCALAPPDATA%\PartyOps`。安装器只为专用网络开放主机端口 `18765`、`18766`。

## UOS 首次安装

```bash
dpkg --print-architecture
sha256sum partyops_1.4.2_amd64.deb
sudo apt install ./partyops_1.4.2_amd64.deb
```

ARM64 机器把文件名替换为 `partyops_1.4.2_arm64.deb`。两个 DEB 必须分别在同架构 UOS V20 上原生构建并验收。

## 系统内升级

1. 管理员进入“管理 → 系统更新”。
2. 导入签名有效的 `partyops_1.4.2.partyops-update`。
3. 系统创建升级前快照，校验平台、架构、版本、文件哈希和 Ed25519 签名。
4. 更新适配器停止服务、安装、迁移并进行健康检查；失败时自动恢复程序和数据库。
5. 主机成功后，协同机按 Windows/UOS 和 amd64/arm64 选择对应制品升级。

## 0017 数据迁移

0017 增加共享根发布人、团队/指定人员范围、正文语义开关、目录成员权限、设备普通用户发布开关、传输交付结果和模型分能力激活。升级保留旧授权；旧指定授权的贡献能力不会被自动扩大。

降级 `0017 → 0016` 会删除这些新增字段和成员关系。已经产生 1.4.1/1.4.2 新业务数据时，应恢复升级前完整备份，不应直接用旧程序继续运行降级后的数据库。

## 回滚与恢复

- 自动回滚：安装、迁移或健康检查失败时由平台更新适配器执行。
- 手工恢复：停止 PartyOps 服务，在恢复向导中选择经验证的 `.partyops-backup`，恢复完成后重新做健康检查和设备心跳检查。
- 文件中心抽查：选择一个主机 DOCX/PDF 和一个协同机文件，分别验证阅读、浏览器下载和当前设备接收。
- 禁止直接覆盖运行中的 SQLite 文件；禁止在没有备份的情况下手工删除迁移表。

## 验收清单

- `/api/v1/health` 返回版本 1.4.2、模式 0017，SQLite 安全版本且 FTS5 可用。
- 管理员与普通用户导航符合有效能力，普通用户直接访问管理路由得到明确拒绝。
- 本机共享目录可添加、重命名、停用、立即同步和修改成员权限。
- 主机与远端 DOCX/PDF 可阅读；CSV/Office/OpenDocument 走 AnyDoc；PDF 走 pdf-inspector。
- 浏览器下载与当前设备接收的最终 SHA-256 等于源文件。
- 目录停用、撤权或设备隔离后，未完成传输立即失败且已完成内容不能再被越权读取。

正式发布前还必须完成[发布就绪判定](release-readiness-1.4.2.md)列出的全部门禁。
