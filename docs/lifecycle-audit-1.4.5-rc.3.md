# PartyOps 1.4.5-rc.3 数据生命周期审查

最后核对：2026-08-25（北京时间）

## 原则

- 已形成历史、关联材料或审计价值的主业务对象不做物理删除，统一采用“影响预检、填写原因、归档、恢复”。
- 规则、模板和目录等配置对象使用“停用、恢复”，停用不得改写已生成的事项、报告或档案。
- 仅个人视图、未形成独立历史的子项和可重新建立的辅助配置允许物理删除；删除仍校验版本与权限。
- 审计日志、系统工作日志、发布记录、备份记录、历史修订和已生效业务事实禁止删除，只允许追加、作废或按法定保留策略清理。

## 验收要求

1. 每个归档动作先返回影响数量且明确 `physical_delete=false`。
2. 所有写操作执行用户权限、设备状态、CSRF 和 `If-Match` 并发校验。
3. 归档对象从活动列表消失、在归档列表出现，恢复后反向成立。
4. 系统审计事件的删除请求必须返回明确错误，不能伪装成功。
5. 归档/恢复均写入审计日志，理由不得包含空白或少于两个字符。

## 可见入口复核

- 今日工作台、通知和系统工作日志属于视图或不可变事实，不提供会破坏历史的删除按钮。
- 备忘录、事项、保存视图、联系人、知识、自动规则、工作日历等辅助对象已有删除或回收站入口。
- 周期事项模板、报告模板、档案类别、授权、AI 白名单等配置对象已有停用/恢复入口；停用不改写已生成业务。
- 会议、学习计划、业务文档、专题空间、人工工作日志、发展党员档案及重要档案使用可恢复归档；其页面均能切换到已归档记录。
- 原始文件中心现在可在“使用中/已停用”之间切换，停用前展示索引文件、业务关联、共享成员和活动传输影响。
