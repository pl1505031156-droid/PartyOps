# 党建智办 PartyOps 1.4.3-rc.8 发布说明

`1.4.3-rc.8` 是未签名候选版，集中修复国产 Linux 安装完成后双击无响应、启动等待失真及诊断文件缺失问题。七个平台仍各自提供一个与系统及架构匹配的安装包。

## 本版修复

- 麒麟、UOS、deepin 与 openEuler 的主程序、协同端、配置向导和更新器改为共用同一个固定运行时，不再把 `libgcc_s.so.1` 等共享库解包成临时可执行文件，避免安全中心反复拦截后无法启动。
- 桌面启动器在执行任何启动动作前创建私有日志；用户配置目录异常时自动切换到稳定后备目录，并生成非空的 `startup-diagnostic.txt`。
- 个人或主机进程退出、PID 文件缺失、系统服务停止、端口未就绪或健康检查超时时立即返回稳定中文诊断码，不再机械等待后只显示笼统超时。
- 启动诊断统一汇总桌面入口、主程序、业务日志、进程、端口、systemd 与 journal 信息；日志与诊断文件权限收敛为当前用户可读。
- 连续双击桌面图标会复用同一个配置工具，启动事务使用当前用户锁串行化，避免多个向导相互覆盖页面地址或残留后台进程。
- 配置工具与主程序健康等待统一延长到 180 秒；真正的子进程退出、目录权限或服务失败仍会立即停止等待。
- 桌面入口会核对健康端点的实际版本；端口上残留旧进程时立即给出 `RUNTIME_VERSION_MISMATCH`，不会打开混合版本页面。
- Windows 无控制台桌面入口增加顶层中文诊断与紧急日志，未预料异常不再表现为黑窗口一闪而过。
- Linux 构建与封装入口统一使用已校验的 Python 3.11 和离线依赖，不再依赖构建机是否偶然预装 `python3` 或 `packaging`。
- 最终 DEB/RPM 增加成品级门禁：四个入口、共享运行时布局、共享库权限、主程序健康端点、桌面打开和确定性启动失败诊断必须全部通过。
- Linux 安装后事务会核对载荷冻结版本和健康端点实际版本；版本不一致时包配置直接失败并保留诊断。

## 验收边界

- AMD64 Linux 成品在 glibc 2.17 环境完成解包后的真实二进制、自检、健康端点、桌面启动和故障诊断闭环。
- ARM64 制品执行同等静态闭包与 QEMU 动态门禁；透明仿真无法等价证明真实 ARM 内核的桌面 PID 归属行为。
- 银河麒麟桌面 V10 SP1 2107/2203/2303/2403/2503 共用 DEB 选包规则；飞腾 D2000/FT-2000、麒麟 9000C/9006C/990、鲲鹏等 `aarch64` 电脑使用同一个 ARM64 DEB，不按 CPU 型号重复拆包。
- 麒麟/UOS 商业系统与 Windows 7 仍无对应真机运行结论，发布页面继续明确标注未真机验证。
