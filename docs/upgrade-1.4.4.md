# PartyOps 1.4.4 升级与回滚

版本：`1.4.4`；数据库：`0020`；最低直接升级基线：`1.4.3-rc.9`。

## 升级前

1. 确认当前系统、包格式和 CPU 架构，禁止强制安装其他架构。
2. 在系统内完成一次备份并验证可读取；同时记录程序目录和业务数据目录。
3. 关闭其他 PartyOps 浏览器页签。主机—协同部署先确认主机可访问；主机换 IP 时先在“网络与协同”完成验证。
4. 从官网 Cloud Studio `/downloads/` 主线路或 GitHub 官方 Release 下载，核对文件名、大小和 SHA-256。

## 升级事务

安装器依次执行：

1. 冻结数据库、配置、证书和协同绑定快照；
2. 校验旧实例归属，只停止安装路径、实例标识和签名/哈希可证明的 PartyOps 进程；
3. 安装新二进制并执行 `0019 → 0020` 增量迁移；
4. 迁移 rc.9 协同配置，尝试把有效旧令牌换发为 v2 设备令牌；
5. 启动最终制品并核验 SQLite/FTS5、运行版本、首页、端口和健康端点；
6. 全部通过后才提交事务并清理临时快照。

401/403 不再无限重试。旧凭据不能自动升级时，系统保留设备身份、绑定和本地数据，将状态设为“需要重新授权”；主机管理员确认后换发新令牌。

## 回滚

健康门禁失败时按相反顺序停止新进程、恢复二进制、配置、证书和数据库快照，再验证旧版本健康状态。自启动项恢复失败只作为独立警告，不得掩盖核心模式是否已经恢复。

不要删除业务数据、未知服务或身份不明的端口占用进程。回滚失败时保留安装日志、启动诊断和快照路径，交由管理员处理。

## 数据迁移说明

- `0020` 只新增 1.4.4 所需表、索引和字段，不把计划日期写入发展党员实际日期。
- 用户删除是可恢复归档；审计、会议、通知历史和文档修订不物理删除。
- 一次性文件打开授权只存令牌哈希，使用、过期或撤销后不可恢复。
- 降级到 `0019` 会删除 1.4.4 新增业务结构，因此只允许安装器使用升级前快照做原子回滚，不建议手工运行数据库降级。
