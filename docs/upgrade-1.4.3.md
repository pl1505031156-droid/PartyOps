# 党建智办 PartyOps 1.4.3 安装、升级与回滚

候选版本：`1.4.3-rc.6`；数据库：`0019`；专业级在线更新基线：`1.4.3-rc.3`。

> 重要：rc.2 的发布签名私钥已经不可恢复，不能安全伪造一份“rc.2 可验证”的新更新目录。因此 rc.2 及更早版本必须从官网手工运行一次与系统和架构匹配的当前 rc.5 安装器并选择原位升级；不需要卸载，也不会删除原数据。已经安装 rc.3/rc.4 的设备可直接使用系统内快速升级。官网和 Release 会持续公开此一次性桥接限制。

## 升级前

1. 确认主机和协同机角色配置，记录当前版本、架构和最近一次有效备份。
2. 系统内更新会自动校验官网目录、更新包和内部安装器；手工下载时仍应核对官网显示的 SHA-256。rc.5 安装器没有 Authenticode 证书，SmartScreen 提示必须与官网说明一致。
3. 停止新的大文件传输，完成数据库在线快照和完整 `.partyops-backup`。

## 日常应用内快速升级

rc.3 起不需要反复到官网寻找安装包。管理员登录后，系统每天至多检查一次签名更新目录；发现新版时只后台下载与当前 Windows/Windows 7/DEB/RPM 和 CPU 架构匹配的单平台签名更新包，不会把其他六个平台安装器一起下载。弱网或关机导致下载中断时，系统会保留已写入片段并在重试时重新计算其哈希，通过严格的 HTTPS Range 范围校验后续传；已经完整校验的同一包不会重复下载。

Windows 主机升级期间，业务程序会立即完成原位替换、迁移和健康检查；两个正在承载升级事务的更新组件由 Windows 在下次系统重启时完成替换，避免更新服务停止自身并留下半安装。页面会持续提示这一次重启建议，重启前不影响已升级业务功能。个人模式、协同机以及 Linux 在更新组件未被占用时无需额外重启。

1. 进入“管理 → 系统设置 → 系统更新”，核对版本、上传时间和中文更新内容。
2. 等待页面显示“下载、签名与哈希校验均已通过”。下载期间可以继续办公，也可以离开更新页面。
3. 点击“开始升级”。安装前会再次明确确认，随后自动创建一致性备份、停止相关服务、原位安装并执行版本和健康检查。
4. 页面短暂断开是正常现象；服务恢复后自动重新连接。失败时恢复旧程序和升级前快照，并保留中文诊断与日志入口。

只有 rc.2 及更早版本建立新签名信任根，或更新助手自身损坏时，才需要手工运行一次当前系统安装器。rc.3 及之后继续使用系统内升级。

## Windows 升级与数据目录

Windows 安装器会分别显示“程序安装目录”和“业务数据目录”。两者都允许使用本机固定磁盘上的自定义路径；升级会读取并保留上次选择。安装器会在覆盖文件前自动等待 `PartyOpsHost` 与 `PartyOpsUpdateService` 停止，不需要用户先进入 `services.msc`。若显示 `UPGRADE_SERVICE_STOP_FAILED`，关闭仍在运行的 PartyOps 窗口后重试，不要选择跳过旧文件。

运行 `PartyOps_1.4.3-rc.6_windows_amd64.exe` 会保留现有主机配置。首次配置可继续使用原目录，也可选择新的本机固定磁盘空目录；迁移会先协调主机与更新服务，使用 SQLite 在线备份取得一致副本，复制并校验全部业务目录，成功后才原子切换配置。失败时恢复原服务状态并保留旧目录和旧配置，不删除原数据。

路径支持中文、空格和非 C 盘。不要选择磁盘根目录、Windows/Program Files、网络盘、移动盘、目录联接或已有另一套 PartyOps 数据的非空目录。迁移成功后也先保留旧目录，完成业务核对和备份后再由管理员决定是否清理。

## 0019 迁移

`0019` 只增加设备真实发行版、包格式、架构和运行能力字段；不重写原有业务表。国家时间规则在程序中不可修改；备忘录和计算草稿不进入数据库。升级保留文件共享、设备、权限、传输、档案和模型数据。

升级失败时执行器恢复升级前程序与数据库。`0019` 是可回滚的加法迁移；仍应优先恢复升级前完整备份，不要把结构降级当作长期回滚方案。

## 验证

- `/api/v1/health`：应用 `1.4.3-rc.6`、数据库 `0019`、冻结 SQLite `3.53.4` 或更高。
- 普通用户能进入备忘录和党员发展计算；不能进入补充材料管理。
- 另一台电脑登录同一账号看不到原电脑备忘录和计算草稿。
- Word 能下载并打开，包含规则版本、时间轴、材料、条款、风险和人工确认项。
- 协同共享、文档阅读、重要档案和更新备份回归无倒退。
- 主机服务连续三次冷启动均在 90 秒内健康；诊断最长等待 180 秒，失败显示稳定诊断码且不打开 URL。
- 本机管理员创建请求走 `127.0.0.1`，局域网成员仍使用向导展示的协作地址。

正式放行仍以官网与 GitHub Release 同步公开的 1.4.3 发布就绪判定为准。
