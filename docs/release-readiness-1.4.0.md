# PartyOps 1.4.0 发布就绪记录

最后验证：2026-08-09（Asia/Hong_Kong）

## 已通过

- 数据库 `0015 ↔ 0016` 自动迁移往返通过；1.4.0 健康检查报告 SQLite 3.53.3、模式 `0016`。
- 后端 164 项测试全部通过；档案贡献授权、字段级校验、Windows 设备共享根、目录审批、传输、评论通知、“我的工作”和平台选包均有自动化覆盖。
- 前端 35 项测试、TypeScript 类型检查和生产构建通过。
- `pip-audit -r backend/requirements.txt` 与 `pnpm audit --prod` 均为“无已知漏洞”；`cryptography` 固定为 50.0.0，`nanoid`/`postcss` 固定为已修复版本。
- Windows 11 x64 本机完成候选安装器的静默安装、服务注册、服务真实启动、恢复策略、专用网络防火墙、文件协议、登录自启、静默卸载和残留检查。
- 冻结主机运行时健康检查通过：版本 1.4.0、SQLite 3.53.3、数据库模式 `0016`。
- Windows 安装后更新服务为 `RUNNING`；主机服务在显式选择 host 前保持停止，选择后可启动到 `RUNNING`。
- Chrome 完成管理员/普通账号的档案贡献、字段级错误、评论提及、通知跳转、层级回复、“我的工作”和非管理员协同页闭环；同状态视觉对照确认现有暖象牙与朱砂体系未被改写。

## 正式发布阻断项

- 后端语句覆盖率 78%、行覆盖率 73%；前端全量语句/行覆盖率 4.87%，均低于 90% 门槛。
- 当前机器只完成 Windows 11 x64 验收，尚未完成 Windows 10 x64 真机及两种角色矩阵。
- 尚未在 UOS V20 amd64/arm64 目标机生成并验收 `partyops_1.4.0_amd64.deb`、`partyops_1.4.0_arm64.deb`。
- 未提供与部署端公钥匹配的隔离发布签名密钥，不能生成可正式导入的签名 `partyops_1.4.0.partyops-update`。
- Windows 候选安装器 Authenticode 状态为 `NotSigned`，只能用于受控试装。
- 20GB 大文件、断线续传、主机重启、Windows 10、UOS 双架构和连续 24 小时三机运行仍需真机专项验收。
- 真实协同 Agent 绑定后的 Windows 主机/协同机 × 管理员/普通账号四组合尚需两台物理机完成；本轮 Chrome 结果不替代设备级真机矩阵。

## 当前判定

源码、Windows x64 候选安装器和 UOS 双架构构建套件可进入受控试装；不得标注为“PartyOps 1.4.0 正式发布”。只有覆盖率、四平台真机矩阵、生产签名和双架构制品全部通过后，才能生成并下发统一更新包。

## 回滚证据

- Windows 验收卸载后：两项服务不存在、PartyOps 安装目录进程数为 0、防火墙规则/文件协议/登录自启均不存在；业务数据目录按设计保留。
- UOS 回滚仍需在对应架构目标机验证 Debian 包级程序回滚与升级前备份恢复。
