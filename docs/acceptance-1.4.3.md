- 前端：180 项测试、类型检查、静态检查与生产构建通过；行覆盖率 `97.10%`，分支覆盖率 `90.00%`。

- Win7 x64/x86：最终 PE 架构/子系统/API-set、UCRT、Python 3.8 与 OpenSSL 门禁通过；安装器还会在每一台目标电脑上启动最终 `PartyOps.exe`，验证 RSA/Fernet、SQLite/FTS5、数据库迁移、同版本健康端点与首页入口，失败即回滚。
- Linux：DEB/RPM 双架构的固定运行时、SQLite 3.51.3/FTS5、OCR、AI、前端、桌面入口、权限、安装后事务与剥离环境变量启动门禁通过；x86_64 使用 glibc 2.17，aarch64 使用 QEMU 动态验证。
- macOS：GitHub 托管 `macos-15` Apple Silicon 与 `macos-15-intel` 原生构建均通过 PKG 安装、Bundle/嵌套代码、`open -na` LaunchServices、原生启动探针日志与版本回读。

## 问题闭环

1. 统信旧局域网监听地址：监听与对外地址分离迁移，避免端口 18766 对失效地址 bind。
2. 个人模式 18775：未知进程不终止，自动选 18775—18875 空闲回环端口；受控旧进程需三项身份证据。
3. Windows 同名服务：SCM 路径、安装位置和卸载元数据共同证明归属，第三方同名服务保持不变。
4. Linux 桌面入口：UTF-8/LF、格式、TryExec、权限和动态启动门禁阻断半配置；麒麟入口经 `/bin/bash`，缺失 HOME 时恢复，桌面 DBus 可信元数据由真实用户写入。
5. 版本错配：页面、健康端点、进程路径与安装载荷共同核对，不打开旧运行时页面。
6. Windows 协议：改为原用户 HKCU 事务注册，拒绝时禁用功能但不回滚主程序。
7. Win7 更新能力：探测安全 Loader API，不只读取 KB 名称。
8. Win11 空白页：静态资源、模块与挂载看门狗提供可复制诊断。
9. UOS 锁超时：锁带 PID/版本/时间，失效锁自动回收，重复双击复用事务。
10. 一事一档：回退创建新版本，保留历史并写审计/工作日志/事件。
11. 文档管理：目录操作始终有入口或明确桌面能力说明。
12. 发展党员：空文件拒绝、稳定对象 URL 与延迟 DOM 清理恢复 DOCX 导出。
13. macOS 双击无响应：Finder 主入口改为原生 C 探针，冻结向导启动前即写 `launch-probe.log`。
14. Win7 rc.8 `CHILD_EXITED`：反馈方未提供 `launcher.log`，不虚构唯一异常栈；rc.9 已覆盖独立 Python 3.8、安全回移与完整目标机启动链，并把任何提前退出变为安装期失败和可复制日志。取得原始日志后若发现新原因，进入下一候选版定点修复。

## 验收边界

- 未取得 Windows 7、银河麒麟/UOS/deepin/openEuler 或 macOS 用户真机交互验收；自动化、QEMU、构建主机和容器结果不写成真机通过。
- Windows 安装器没有 Authenticode 商业签名。macOS PKG 只有 ad-hoc 签名、没有 Developer ID 和 Apple 公证；官网必须保留 Gatekeeper 安全打开步骤且不得建议全局关闭。
- rc.3 在线更新信任根保持不变；本机未找到匹配离线 Ed25519 私钥时，不生成 rc.9 `.partyops-update` 或更新目录，也不擅自轮换公钥。
