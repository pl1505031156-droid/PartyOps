# 党建智办 1.4.0：UOS 一键安装、升级与多设备协同

最后更新：2026-08-04

## 1. 先确认处理器架构

在每台统信电脑执行：

```bash
dpkg --print-architecture
uname -m
```

对应关系：

| 电脑 | 结果 | 安装包 |
| --- | --- | --- |
| 海光、兆芯、Intel、AMD 等 x86 电脑 | `amd64` / `x86_64` | `partyops_1.4.0_amd64.deb` |
| 飞腾 D2000/8 等 ARM 电脑 | `arm64` / `aarch64` | `partyops_1.4.0_arm64.deb` |

架构不同不能混装。D2000/8 出现“amd64 架构不匹配”是因为安装包选错，不是系统损坏；禁止使用 `--force-architecture`。

## 2. 安装后的入口

安装完成后，统信启动器和日常用户桌面都会出现一个“党建智办”图标。首次双击进入“主机 / 协同终端”配置向导；配置完成后再次双击直接进入系统。升级 1.4.0 不会增加第二个图标、第二个业务服务或第二份数据库。

## 3. 推荐方式：双架构离线安装目录

发布目录同时包含两种架构的 `.deb`、校验清单和 `install.sh`。把整个目录复制到任意一台 UOS V20 电脑，执行：

```bash
cd PartyOps-1.4.0-UOS-amd64-arm64-offline
bash install.sh
```

安装器会：

1. 自动识别本机 `amd64` 或 `arm64`；
2. 只读取匹配架构的 SHA-256 清单；
3. 校验 `.deb`；
4. 安装或原位升级同一个 `partyops` 软件包；
5. 把桌面图标创建到日常账号。

日常账号没有 sudo 权限时，可由管理员执行：

```bash
sudo -i
cd /data/home/日常用户名/PartyOps-1.4.0-UOS-amd64-arm64-offline
bash install.sh --desktop-user 日常用户名
exit
```

这正是“普通账号权限不够、root 又提示不要直接运行”场景的固定解法。必须填写实际桌面用户名，安装后退出 root，再从日常账号双击图标。

如果目录中只有另一种架构的包，脚本会用中文提示应复制哪个文件，不会联网编译，也不会强行混装。

当前仓库若只有 `PartyOps-UOS-build-kit.zip`、没有两种 `.deb`，说明它还是“目标机原生构建套件”，不能当作已经完成目标机验收的一键安装包。必须先按下一节分别在 amd64 和 ARM64 UOS V20 电脑构建，再汇总成双架构发布目录。

## 4. 没有预构建 `.deb` 时：在 UOS 原生构建

PyInstaller 不能把 amd64 程序可靠交叉编译为 ARM64，因此两种包必须分别在相应 UOS V20 目标机原生构建。

在 Windows 准备完整双架构离线构建套件：

```powershell
.\scripts\prepare-uos-offline.ps1 -Architecture all
.\scripts\package-uos-build-kit.ps1
```

复制 ZIP 和 `.sha256` 到对应 UOS 目标机：

```bash
sha256sum -c PartyOps-UOS-build-kit.zip.sha256
unzip PartyOps-UOS-build-kit.zip
cd PartyOps
bash install.sh
```

若当前架构没有预构建包，安装器才进入原生构建流程。套件自带架构匹配的 CPython 3.11.15 和 Python 离线轮子，不依赖 UOS 软件源中的 `python3.11-venv` 或 `python3.11-dev`。构建工具和 Tesseract 缺失时，优先使用 `vendor/system-debs/<架构>/`，否则使用当前已配置的可信 UOS 软件源。

构建要求：

- 统信 UOS V20，glibc ≥ 2.28；
- 目标机架构必须与待构建包一致；
- 至少 4 GiB 可用空间；
- `gcc`、`g++`、`make`、`tar`、`zstd`、`dpkg-deb`；
- Tesseract 和 `chi_sim`，以便把 OCR 引擎与中文模型打入包内。

在 amd64 和 ARM64 机器各构建一次后，汇总 `artifacts/`，在 Windows 执行：

```powershell
.\scripts\package-uos-release.ps1
```

生成 `PartyOps-1.4.0-UOS-amd64-arm64-offline.zip` 及 SHA-256。该 ZIP 才是可在不同国产电脑上自动选包的一键发布目录。

## 5. 第一台电脑配置为主机

1. 双击桌面“党建智办”。
2. 选择“配置为主机”。
3. 选择本机真实固定局域网 IP，例如 `192.168.10.20`，不要使用 `0.0.0.0` 或其他电脑的 IP。
4. 端口默认 `18765`。
5. 使用既有数据目录；升级时不得选择新的空目录覆盖旧配置。
6. 创建管理员账号，并在“系统设置 → 用户与权限”创建协同账号。
7. 在“设备与协同中心”设置设备上限并生成 10 分钟一次性入网码。

主机保存唯一数据库、附件、原始文件索引和固化文件。SQLite 不得放到网络共享盘。防火墙只向可信办公网段开放主机端口，禁止公网映射。

## 6. ARM64 D2000/8 或其他电脑配置为终端

在 ARM64 电脑使用 `partyops_1.4.0_arm64.deb`，或在双架构目录运行 `bash install.sh`。安装后：

1. 双击“党建智办”；
2. 选择“配置为协同终端”；
3. 主机地址填写 `https://主机IP:18765`；
4. 填写本机设备名称和主机生成的完整一次性入网码（末尾包含 CA 指纹）；
5. 可选一个本机共享文件夹，并选择终端灾备目录；
6. 主机管理员批准设备、共享根和具体访问能力；
7. 使用主机创建的协同账号登录。

终端不保存可写业务数据库。任务、评论、材料、报告和文件预览都通过主机授权接口完成，SSE 正常时两端变化 3 秒内可见，断线时降级为短轮询。

OCR 规则：

- 终端共享目录的正文/OCR 索引在终端低负载生成；浏览器上传到事项的图片或扫描 PDF 仍由主机执行 OCR；
- 两种架构的 1.4.0 包都内置同架构 Tesseract 和 `chi_sim`；
- 若把 ARM64 终端切换为灾备主机，其本机 OCR 可独立运行。

## 7. 1.0.0 原位升级

不需要卸载。优先在主机“管理 → 系统更新”导入 `partyops_1.4.0.partyops-update`；只有更新助手损坏时，才按电脑架构双击 1.4.0 `.deb` 或运行 `bash install.sh`。包名仍为 `partyops`，统信安装器会识别为升级。

升级前：

1. 在 1.0.0 中执行手动备份；
2. 把备份和 `.sha256` 复制到第二台电脑；
3. 记录当前数据目录、主机 IP 和端口；
4. 确认只有一台主机在线写入。

升级保留 `/var/lib/partyops`、用户数据目录、配置、终端配对和原始文件。首次启动会先做 `pre-upgrade` 备份；数据库模式升级为 `0016`。详见 [1.4.0 安装升级](upgrade-1.4.0.md)。

## 8. 多设备现场验收

1. 主机管理员在“设备与协同中心”设置 1—20 台上限；每台终端分别登录本机桌面账号并用一次性入网码加入。
2. 终端创建评论或更新事项，主机 3 秒内可见。
3. 主机退回、转交、提交审核，终端能收到持久化提醒。
4. 上传扫描件，主机完成 OCR 后终端可搜正文。
5. 纳管主机原始目录，确认终端看不到主机绝对路径。
6. 文件与事项、周报、日志双向关联；固化后原文件移走仍可从归档附件找到。
7. 发布周报并导出 Word、Excel。
8. 主机手动备份，终端补拉 `.partyops-backup` 与 `.sha256`。
9. 重启主机和已纳管终端，桌面图标、数据、证书和设备状态仍在；离线终端上线后继续未完成传输或升级。
10. 在主机执行：

```bash
bash packaging/uos/target-acceptance.sh https://主机IP:18765
bash packaging/uos/soak-test.sh https://主机IP:18765 3600 10
```

快速验收记录写入 `artifacts/uos-target-acceptance.txt`；连续运行检查写入带时间戳的 `artifacts/uos-soak-test-*.txt`。正式全面使用前建议把持续时间改为 `86400` 秒进行 24 小时检查。

## 9. 常见故障

- `无法定位 python3.11-venv/python3.11-dev`：旧安装套件问题；1.4.0 自带独立 Python，不再请求这两个包。
- `权限不够`：用普通账号执行时输入 sudo 密码；若账号无 sudo，使用 `bash install.sh --desktop-user 用户名`。
- `架构不匹配`：D2000/8 攚用 `arm64.deb`，海光/x86 使用 `amd64.deb`。
- `clang not found`：1.4.0 构建脚本显式使用 GCC。
- `No matching distribution found`：检查是否携带了 `vendor/wheels/<本机架构>/`，不要把 amd64 wheelhouse 复制给 ARM64。
- 安装失败时查看 `artifacts/one-click-install.log`，不要删除业务数据目录。

### 协同电脑入网显示 HTTP 400

旧界面可能把较长的入网码显示成单行并在右侧截断。修复后的主机页面会显示字符数、自动换行，并提供“复制完整入网码”按钮；协同端也会自动清除复制时混入的空格和换行。

1. 在主机“设备与协同中心”重新生成入网码，并在 10 分钟内使用；每个入网码只能成功使用一次。
2. 点击“复制完整入网码”，不要只复制当前屏幕可见部分。当前格式通常为 89 个字符，包含一个英文句点，句点后的 64 位十六进制内容必须与页面显示的“主机 CA 指纹”完全一致。
3. 主机地址必须逐字填写页面给出的地址，包括 `http://` 或 `https://` 和端口；不要自行更换协议。
4. 设备名称应与已经入网的设备不同。
5. 若仍提示“入网码无效或已过期”，关闭旧入网窗口，在主机重新生成一个新码后立即复制使用。

未升级修复版时的临时方法：在主机页面从入网码第一个字符开始选中到最右侧全部内容；如果界面无法完整选择，可将“句点前的一次性密钥＋英文句点＋页面单独显示的 64 位 CA 指纹”拼成完整入网码。不要加入标签、冒号或空格。

## 10. 后续版本如何更新

当前每台 1.0.0 电脑需要最后手动安装一次当前架构的更新助手桥接包。已安装 1.1.3 的电脑以后不再解压源码或重复运行构建脚本：

1. 发布负责人在两种 UOS 架构分别构建同一新版本 `.deb`；
2. 在隔离发布机使用离线保存的 Ed25519 私钥生成签名 `.partyops-update`；
3. 主机管理员进入“系统设置 → 系统更新”，导入更新包；
4. 主机导入 1.4.0 更新包并完成健康检查后，低版本协同电脑进入系统时显示更新内容并要求确认；
5. 主机自动登记全部有效终端；低版本终端不更新不能进入业务页面，点击“开始更新”后自动安装并进入系统；
6. 离线终端下次上线继续，已经安装目标版本的终端不会重复安装；
7. 页面显示全部目标成功后，执行一次手动备份并检查终端灾备副本。

更新失败时不要反复点击。保留更新记录、升级前备份和 `journalctl -u partyops -n 200 --no-pager` 输出；系统会尝试恢复旧程序和数据库快照，确认只有一台主机在线后再处理。
