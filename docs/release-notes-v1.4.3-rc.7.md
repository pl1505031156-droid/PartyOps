# 党建智办 PartyOps 1.4.3-rc.7 发布说明

`1.4.3-rc.7` 是未签名候选版，集中修复首次配置、跨版本启动、Win7 首页 500 与国产 Linux 安装/双击启动问题。七个平台仍各自提供一个与系统及架构匹配的安装包。

## 本版修复

- Windows 个人模式在创建管理员前重新确认服务健康；连接结果不明确时不自动重发敏感信息，而是显示中文原因并让用户明确重试，避免直接暴露 `WinError 10061`。
- Windows 桌面入口不再弹出黑色控制台；配置或进程失败时显示中文诊断码和日志位置。
- 浏览器入口加入运行版本指纹，旧页面只自动刷新一次，避免 rc.5 页面与 rc.6/rc.7 服务长期混用。
- 旧 PartyOps 服务仍登记但服务管理程序已损坏时，安装器会在核验服务归属后通过 Windows 服务控制器停止并原位修复，不再要求先手工卸载；同名第三方服务仍会安全阻断。
- 主机重试不再误读上次启动的失败状态；模式切换回滚必须确认旧服务真正恢复运行，否则保留恢复快照与中文诊断。
- Win7 Python 3.8 静态首页兼容新版 Starlette，x64/x86 首页和健康端点均完成源码运行验证。
- Win7 安装器按安全 DLL 加载 API 的真实可用性判断系统更新，不再因后续汇总更新替代旧 KB 登记而误报。
- Linux 启动脚本核对 PID 对应的真实可执行程序，进程提前退出时立即显示中文诊断；不再因 PID 复用而双击无反应。
- DEB 安装流程避开下载目录对 `_apt` 的访问限制；包配置失败直接输出失败阶段、日志尾部和恢复命令。
- DEB/RPM 安装后使用统一事务执行运行时、页面、健康端点、systemd 与更新服务检查，图形软件中心在 95% 处失败时也能留下稳定诊断码。
- Linux 系统内更新只收敛 PartyOps 自身的半配置状态，检测到其他未完成配置的软件包时停止并提示人工处理，不再批量修改无关软件。
- 事项负责人、创建人和管理员可以删除误建事项；系统保留审计记录并阻止覆盖其他电脑刚完成的修改。
