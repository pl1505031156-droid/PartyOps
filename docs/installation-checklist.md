# 党建智办 1.4.0 单位电脑安装与验收清单

最后更新：2026-08-04

## 一、正式交付文件

- `partyops_1.4.0_amd64.deb`
- `partyops_1.4.0_arm64.deb`
- `partyops_1.4.0.partyops-update`
- 每个文件对应的 SHA-256 清单
- `党建智办-1.4.0-更新说明.txt`
- 可选的、与主程序分离的签名 `.partyops-modelpack`

只有 `PartyOps-UOS-build-kit.zip` 时仍处于目标机构建阶段，不能当作已经通过双架构验收的正式安装包。模型包也不能替代主程序更新包。

## 二、安装前

1. 每台电脑执行 `dpkg --print-architecture`。
2. 海光、兆芯、Intel、AMD 一般使用 `amd64`；飞腾 D2000/8 使用 `arm64`。
3. 主机使用固定地址或路由器 DHCP 地址保留。
4. 确认只有一台主机保存可写业务数据库。
5. 升级前在系统内创建备份，并确认第二台电脑已有灾备副本。
6. 不卸载旧版，不删除 `/var/lib/partyops`。

## 三、新电脑安装

1. 双击与架构匹配的 `.deb`。
2. 在统信安装器中输入管理员密码。
3. 确认桌面和启动器只有一个“党建智办”图标。
4. 主机选择真实局域网 IP，默认端口 18765/18766。
5. 协同电脑粘贴完整一次性入网信息，等待 Agent 心跳成功。
6. 主机批准设备、用户和目录权限。

## 四、已安装旧版本

1. 主机进入“管理 → 系统更新”。
2. 导入 `partyops_1.4.0.partyops-update`。
3. 检查签名、磁盘、数据库完整性和升级前备份。
4. 主机升级到 1.4.0 / 0016 并通过健康检查。
5. 协同电脑确认更新后，Agent 安装匹配架构版本、自重启并自动进入系统。
6. 主机确认所有启用设备版本一致。

更新助手损坏时才允许用同架构 `.deb` 原位修复。禁止 `--force-architecture`。

安装程序结束前必须确认 `partyops-updater.service` 已启用且处于运行状态；更新助手未启动时不得把电脑登记为安装成功。

## 五、功能验收

- 五域导航和旧路由重定向正常。
- 今日工作台每个数字可进入对应结果。
- 周、月、年度日历能显示任务、内部节点、周期、汇总和节假日。
- 长期任务可以预览未来 12 次、暂停、终止、跳过单次和临时改期。
- 已完成事项自动进入草稿周/月/季/年汇总；重新打开后草稿投影可撤销，发布快照保持。
- 任务详情能查看双向关联和完整活动时间线。
- 原始文件中心只扫描目录和属性，点击由 UOS 默认程序打开。
- 工作日志显示北京时间、操作人员、动作和状态变化。
- 重要档案、扫描件、审计和备份保持完整。
- 主机与 amd64/ARM64 协同电脑共享同一任务、报告、档案和通知数据。
- 任务修改 3 秒内可见；SSE 失败时轮询降级。
- 设置页显示业务/设备端口、数据库完整性、投影状态、备份时效和设备版本。
- 系统内更新历史显示版本、时间、内容和每台设备结果。
- 今日和日历只增加淡墨画面、农历与节气，原有卡片、表格、按钮和导航位置没有结构性变化。
- 切换“减少装饰”后画面隐藏、农历保留；模型缺失或损坏时事项、文件、档案和协同仍可正常使用。
- 导入签名模型包后，本地推荐只处理非敏感事项和已授权受管材料；原始文件中心正文不进入模型。

## 六、命令验收

在 UOS 主机执行：

```bash
dpkg-query -W -f='${Version} ${Architecture}\n' partyops
sudo ss -lntp | grep -E ':18765|:18766'
bash packaging/uos/target-acceptance.sh https://主机IP:18765
bash packaging/uos/soak-test.sh https://主机IP:18765 3600 10
```

正式发布还必须完成 7 天三机连续运行、双架构原生构建、签名更新、迁移失败回滚和全量覆盖率门槛。

## 七、失败处置

保留：

- `/var/lib/partyops`
- 升级前 `.partyops-backup`
- `artifacts/one-click-install.log`
- 脱敏诊断包

停止反复安装，按诊断编号定位。不要复制 WAL 写入中的数据库，不要让新旧两台主机同时写入。
