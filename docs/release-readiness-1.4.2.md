# PartyOps 1.4.2 发布就绪判定

最后验证日期：2026-08-11（北京时间，UTC+8）
当前结论：**NO-GO / 不得标注稳定正式版**

## 已通过

- 版本 1.4.2 与数据库模式 0017 的源码、迁移兼容和生产前端构建通过。
- 后端 213 项、前端 41 项、Sites 4 项测试通过。

- 传输最终权限复核、源变化检查、SHA-256、显式完成、同根扫描串行和正确计数已有回归。
- pnpm 与 Python 生产依赖审计均无已知漏洞；cryptography 已升级到 50.0.0。
- 开源终审已关闭包内公钥信任、固定演示口令、备份炸弹、SVG inline、AI SSRF、设备 IP 冒充、Windows 数据目录 ACL、Agent 静默失败和长期 URL 设备令牌问题。

## 发布规则

只有上表全部关闭后，才允许：

1. 生成并标记 `PartyOps_1.4.2_windows_amd64.exe`、两个 DEB 和统一更新包为正式制品。
2. 删除可回溯所需的候选证据之外的旧构建文件。
3. 推送正式发布提交、创建 Git 标签和 GitHub Release。
4. 在 README 中把下载状态改为“稳定正式版”。

不得降低覆盖率阈值、排除核心业务源码、用 Windows 模拟结果替代 UOS 真机或把未签名候选改名冒充正式包。

## 2026-08-09 再复检

- Chrome 真实页面复核通过主机管理员与普通协同账号登录、权限导航、文件中心和禁止访问页；普通账号可阅读 DOCX 结构化内容，控制台无应用错误。
- DOCX、PDF、CSV 均在文件中心形成结构化阅读视图；档案空表提交返回明确中文必填提示，没有复现“请检查标记字段后重试”。
- 后端 201 项、前端 41 项、Sites 4 项再次通过；生产构建、类型检查、Python 编译与生产依赖审计通过。
- 覆盖率门禁再次失败，且开发源码环境 SQLite 安全版本检查失败。依用户明确要求已生成 Windows x64 未签名测试候选；冻结运行时使用 SQLite 3.53.3 并通过安装/卸载验证，但它不改变正式发布 NO-GO 判定。

## 解除门禁所需外部条件

- UOS V20 amd64、UOS V20 arm64 和 Windows 10 x64 可执行目标机。
- 与部署端公钥匹配的隔离 Ed25519 发布密钥，以及有效 Windows 代码签名证书。
- 连续 24 小时的可用验收窗口。

这些条件满足后，按[1.4.2 验收记录](acceptance-1.4.2.md)和[安装升级说明](upgrade-1.4.2.md)复验。
