## 3. 已验证的关键回归

- UOS 重绑请求缺少、无效、不匹配的一次性头均返回精确 403；匹配时可入网；同一头不能绕过其它写接口的 Origin 门禁。
- `2026-08-28 18:00` 按北京时间保存为 `2026-08-28T10:00:00Z`，再次展示恢复为 18:00；显式时区输入保持同一瞬时。
- 档案年度候选只有在用户明确确认后进入导入，错误年份和未确认提交均被拒绝。
- 发展党员节点提供中文标题；未知内部键显示“待确认节点”，不会直接出现在生产界面。
- 爱发电重复回调、具体赞助者查询、分页补偿、网络失败、人工“子木”和二维码静态降级均有自动回归。
- macOS 构建脚本执行原生入口前置探针、由内向外递归签名和 Team ID 一致性检查；LibreOffice 越界符号链接与错误架构会阻止打包。

## 4. 阻塞项与禁止动作

本机没有以下经许可审计、带来源清单与许可证的目标架构 LibreOffice headless 闭包：Windows AMD64/x86、Linux AMD64/ARM64、macOS Intel/Apple Silicon。也没有本轮 UOS/麒麟 ARM64 和两种 Mac 的原生交互环境。因此：

1. 九个平台安装包均未生成，支持矩阵全部保持 `unavailable`。
2. 不创建 `v1.4.5-rc.5` 标签，不上传 Cloud Studio/GitHub，不切换 EdgeOne Preview/Production。
3. 官网与在线更新继续提供 rc.4；本地官网虽然构建通过，仍不部署 rc.5 文案。
4. 不用 Windows/Linux 交叉结果冒充 macOS 或 ARM 原生验证，也不把系统现装 LibreOffice 复制成未经审计的发布闭包。

## 5. 解除阻塞后的固定顺序

准备每个平台的 LibreOffice 来源清单、许可证、哈希和原生二进制闭包后，依次执行：原生制品构建 → 全新安装 → `0024→0025` 覆盖升级 → 公文 DOC/DOCX/WPS 转换 → 协同/提醒/回滚 → macOS Team ID/Finder 验证 → 制品签名清单 → Cloud Studio `/downloads/` 上传 → 公网 EOF 回读与哈希 → GitHub 预发布 → EdgeOne Preview → Chrome 验证 → Production。

任一门禁失败均保留 rc.4 生产版本，不进行部分替换。
