# PartyOps 体检问题核实与首轮安全加固记录

日期：2026-08-04
输入来源：`output/PartyOps项目体检报告-2026-08-04.md`、`output/项目解剖报告-2026-08-04.md`
核实范围：两份报告中的“不足、风险与安全漏洞”章节；未把报告结论直接视为事实。
安全策略：仓库内未发现 `SECURITY.md`，因此按产品既有的单主机、可信局域网、用户与设备双重授权边界核实。

## 本轮优先修复

| 问题 | 核实结论 | 本轮处置 |
| --- | --- | --- |
| 登录可无限失败重试 | 已确认 | 增加账号与来源地址双维度节流，默认账号 5 次、来源 20 次，锁定 15 分钟；状态只保存 SHA-256 摘要并设置容量上限。 |
| HTTPS 会话 Cookie 固定为非安全 Cookie | 已确认 | 改为随 `tls_enabled` 自动设置 `Secure`，继续保留 `HttpOnly` 与 `SameSite=Lax`。 |
| 首次配置检查与管理员写入非原子，且可被局域网抢占 | 已确认 | 仅允许主机本机发起；“检查用户数＋创建管理员”放入应用写锁，消除并发窗口。 |
| 演示数据默认开启 | 已确认 | `seed_demo` 默认改为 `false`，只有显式配置且非生产环境才允许生成演示数据。 |
| 登录节流器自身可能被大量伪造账号撑大 | 加固复核时发现 | 增加可配置的 4096 条默认容量上限，超限淘汰最旧状态。 |
| 旧式备份配对令牌长期有效 | 已确认 | 增加默认 365 天固定有效期；到期后服务端自动撤销并返回 `PAIRING_EXPIRED`，创建和管理界面显示到期时间。新版设备证书通道不受影响。 |

选择依据：以上问题具有明确入口、可达路径和安全影响，修复改动集中、兼容性风险较低，且直接影响首次部署与管理员账号安全。

## 工程不足核实摘要

- 前端页面覆盖率偏低、部分 Vue/Python 文件过大：真实存在，属于下一轮可维护性与回归能力重点，不宜与本轮安全补丁混成一次大规模重构。
- 前端生产构建可通过，但 `vendor-ui` 约 788 KiB，仍有分包优化空间；纸张纹理资源约 2 MiB，属于性能优化项。
- 前后端类型契约存在手工双写：真实存在，建议后续从 OpenAPI 生成客户端类型。
- 当前工作区 `.git` 不完整，无法用提交历史证明私钥是否曾入库，也无法按“一问题一提交”留痕；本轮以精确补丁、测试输出和本文档代替。
