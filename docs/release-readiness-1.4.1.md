# PartyOps 1.4.1 发布就绪判定

判定日期：2026-08-09

## 总结

- 功能实现：**完成**。
- Windows 11 x64 隔离候选：**通过**。
- 正式全平台发布：**NO-GO**。

## 已关闭

- 0017 升级/降级迁移与 1.3.4、1.4.0 候选兼容契约。
- 普通协同用户发布和管理本机真实目录。
- 团队/指定人员的浏览、下载、发送与目录管理权限。
- 单文件、多选 ZIP、文件夹 ZIP 的统一下载后端，浏览器/当前设备双交付。
- 逐分块权限复核、20GB 代码限制、哈希校验、重名避让、审计和过期清理逻辑。
- 主机/协同机 × 管理员/普通用户的能力驱动导航与明确无权限页。
- embedding/LLM 分能力模型管理、BGE CLS 池化与固定 llama.cpp 运行时。
- Windows 11 x64 安装、系统集成、协议发布、真实下载与卸载闭环。

## 放行条件

1. 在 Windows 10、Windows 11、UOS amd64、UOS arm64 分别完成主机和协同机角色、管理员和普通用户矩阵。
2. 把前后端全仓行覆盖率提升至至少 90%，重新执行类型检查、构建和依赖审计。
3. 完成 20GB、断线续传、主机重启、权限中途撤销和连续 24 小时测试。
4. 升级到含 CVE-2026-69247 正式修复的稳定 cryptography，或由发布责任人完成书面风险接受；本项目默认选择前者。
5. 在隔离发布环境完成 Windows Authenticode、统一包 Ed25519 和模型包签名，并执行升级、原位回滚和备份恢复。

## 回滚

- 候选 Windows 安装器已验证卸载清理系统集成且保留业务数据。
- 0017 刚迁移且未产生新业务写入时可降级到 0016；否则恢复升级前 `.partyops-backup`。
- UOS 正式验证必须使用上一版本同架构 DEB 与升级前备份完成程序、数据库双回滚演练。
