## 不可降级的阻断项

1. 不得取消自定义目录安全检查；只修复误判。网络盘、移动盘、磁盘根、重解析点、系统目录和确实允许普通用户替换服务文件的路径继续拒绝。
2. 不得把 Inno 语法探针、旧证明包或手工拼接目录作为最终安装器。
3. 不得用忽略规则掩盖 Win7 依赖漏洞；安全回移组件必须有源码提交、补丁、复现测试、SBOM/VEX 和架构匹配轮子证据。
4. 不得在没有最终制品时预填大小、SHA-256 或上传时间。
5. GitHub `prerelease=false` 只是普通 Release 属性，不代表真机验证或稳定版承诺。
6. 国产 Linux 的 `cryptography` 去重、ARM64 语义/LLM 闭包和 glibc 2.17 门禁必须严格通过，禁止基础构建降级。

## 用户接受的验证边界

依据用户 2026-08-14 与 2026-08-17 的明确决定，当前缺少 Windows 7、麒麟、UOS、deepin、openEuler 真机不再单独阻断对应制品；前提是实际构建、冻结自检、静态兼容、依赖闭包、安全、格式和哈希门禁全部通过。官网、GitHub Release、发布清单和安装器持续标注“未真机验证”。后续使用反馈形成新的现场记录，不能倒填本次验收。

## 发布与回滚

发布顺序固定为：干净源码提交与不可变 `v1.4.3-rc.4` 标签 → 七包重建 → 逐件本地验收/扫描 → CloudStudio 上传并验证 Magic、长度、Range 与 SHA-256 → GitHub 普通 Release → EdgeOne 项目 `makers-gjuf8qcecmi3` → 桌面与移动端回归。

回滚只恢复已保留的旧官网部署和 rc.3 链接；不移动标签、不覆盖历史资产、不删除用户数据。依据用户决定，rc.4 在线核验完成后单独移除 rc.2 Release/资产，rc.3 作为应用内升级信任基线继续保留。
