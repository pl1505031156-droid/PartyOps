# PartyOps 1.4.5-rc.1 升级与回滚

版本：`1.4.5-rc.1`；数据库：`0022`；最低直接升级基线：`1.4.4`。

## 升级前

1. 确认系统、包格式和 CPU 架构，禁止强制安装其他架构。
2. 在“备份与灾备”完成一次备份并验证可读取，同时记录程序目录与业务数据目录。
3. 关闭其他 PartyOps 浏览器页签；主机—协同部署先确认主机可访问。
4. 从官网国内 `/downloads/` 主线路或 GitHub 官方 Release 下载，核对文件名、大小与 SHA-256。

## 升级事务

安装器依次执行：

1. 冻结数据库、配置、证书、更新状态和协同绑定快照；
2. 校验旧实例归属，只停止可由安装路径、实例标识和进程身份共同证明的 PartyOps 进程；
3. 安装新二进制并依次执行 `0020 → 0021 → 0022` 加法迁移；
4. 启动最终制品并核验 SQLite/FTS5、运行版本、首页、静态资源、端口与健康端点；
5. 全部通过后才提交事务并清理临时快照。

## 重新选择运行身份

升级完成后，可在“设置 → 运行身份与协同 → 重新启动配置向导”重新选择：

- 个人模式：只在当前用户会话运行，不注册系统服务；
- 主机模式：需要一次管理员授权，用于局域网协同；
- 协同机模式：连接现有主机，不在本机创建主机服务。

向导会读取现有数据目录和管理员状态，不重复创建管理员，也不会静默改回默认目录。主机级重新配置请求只接受本机管理员；普通用户不能改写主机模式标记。

## 回滚

健康门禁或角色切换失败时，按相反顺序停止新进程，恢复旧二进制、配置、证书、数据库快照、服务与受控防火墙规则，再验证旧版本健康状态。不得删除业务数据、未知服务或身份不明的端口占用进程。

## 数据迁移说明

- `0021` 只新增会议出席、决议事项、中心组计划与专题、发展党员参考计划快照及业务会议专属字段。
- `0022` 新增业务附件幂等上传标识、30 天可恢复删除字段、清理状态和唯一约束；同一物理文件仍按 SHA-256 去重保存。
- 历史会议缺少新字段时显示“待补充”，不伪造参会人员、材料、表决或合规结论。
- 参考日期、法定边界和实际日期独立保存；参考计划不会覆盖实际组织决定。
- 降级到 `0020` 会移除新业务结构和附件恢复元数据，因此只允许安装器使用升级前快照做原子回滚，不建议手工运行数据库降级。
