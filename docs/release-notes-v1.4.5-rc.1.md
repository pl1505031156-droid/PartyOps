# 党建智办 PartyOps 1.4.5-rc.1 发布说明

`1.4.5-rc.1` 以真实党务工作闭环为核心，将“三会一课”、党委（党组）理论学习中心组学习和发展党员从通用记录升级为独立业务模块，并补齐已配置设备重新选择个人、主机或协同机身份的入口。本版数据库模式为 `0022`；安装器升级前保留数据库、配置、证书和绑定快照，健康门禁失败时不得提交迁移。

## 三会一课与中心组学习

- 新增“党务”一级工作域和“三会一课”独立工作台，提供年度台账、会议创建、材料检查、决议落实、关联事项和 Word/Excel 导出。
- 内置支部党员大会、支委会、党小组会、党课四套版本化模板，按“计划—准备—召开—记录—决议落实—归档”形成闭环；系统只作频次与材料风险提示，不替代党组织判断会议或表决是否有效。
- 新增党委（党组）理论学习中心组独立模块，覆盖年度学习计划、专题安排、集体学习研讨、考勤和发言、调研课题、成果转化与归档。
- 中心组年度计划及专题支持并发版本校验；管理员、创建人和明确指定的学习秘书可维护，普通已登录用户可查看，未登录和跨实例请求不能读取。
- 今日工作台显示本季度应开展场次、待归档记录、逾期决议和发展党员关键提醒，不再要求用户在多个页面重复核对。

## 发展党员参考计划

- 将“快速测算、人员台账、材料清单、单位口径”集中到统一的“发展党员”模块。
- 输入入党申请书提交日期后生成可编辑参考计划，并将实际日期、法定边界和内部参考日期分栏展示；参考日期不写入实际组织决定。
- 修改实际日期时先预览后续计划变化，用户明确确认后才更新；规则版本和假设按档案保存，后续模板调整不会静默改写历史数据。
- Excel 导出防止公式注入，敏感导出写入操作人、范围、文件格式和 SHA-256 审计记录，响应不进入浏览器缓存。

## 配置、启动与跨平台修复

- 设置页新增“重新配置运行身份”，可重新打开配置向导，并在个人、主机、协同机之间自由选择；已存在管理员和业务数据会被保留。
- 只有本机管理员可以提交主机级重新配置请求；普通用户和远程请求不能改写主机标记。协同机可通过受控深链进入配置向导。
- 配置向导新增显式重新配置状态，复用统一启动状态机，避免已经配置后只能进入主界面、无法再次选择角色。
- macOS 原生入口在启动冻结运行时前清理 PyInstaller、Python、DYLD/LD 继承状态并设置安全 PATH 与 UTF-8 运行环境；前置探针保留子进程标准错误、架构、PID、退出码和资源路径。Apple Silicon 与 Intel PKG 已在对应原生 Darwin 主机完成全新构建、安装、重复运行时自检、LaunchAgent 和真实 LaunchServices 启动门禁，专门回归用户日志中“入口进入后桌面子进程以 255 退出”的故障。
- macOS 包内原生依赖自检使用干净子进程环境并为大型 `llama-server --version` 探针保留 120 秒，避免继承冻结环境导致动态库加载错误，也避免将 Intel 首次加载约 38 秒误判成启动失败。

## 官网与交互

- 官网亮点同步为今日工作、三会一课与中心组、发展党员时间轴、事项与汇总、文件与档案、本地协同安全。
- 微信社群和赞助二维码改为“悬停预览、点击固定”：鼠标可从按钮移动到二维码，微信/支付宝页签可点击和键盘切换，支持关闭按钮、点击外部和 Esc 关闭；触屏设备使用可操作的底部面板。

## 多文件与本地智能

- 一事一档、档案扫描件和收件入口支持一次选择多个文件，逐文件显示等待、进度、成功、失败、取消和重试；上传队列并发数固定为 2，单个文件失败不会回滚其他成功文件。
- 批量上传时每个文件创建独立材料项和首个版本；已有材料的“上传新版本”仍只处理一个文件，避免把无关文件混成版本链。
- 业务附件支持填写原因的 30 天可恢复删除；已定稿文件删除后恢复为“待确认”，过期清理只删除没有其他有效或可恢复引用的物理文件。
- 设置新增完全在本机运行的硬件检测与可选隔离性能测试，按系统、架构、内存、显存、磁盘和 GPU 后端推荐从 Needle、BGE 到 Qwen3 235B-A22B 的 12 个档位，并显示推荐量化、线程和上下文配置。
- 官网新增“本地智能模型”二级页。小模型仅在签名包完成许可、哈希和运行门禁后提供直传；大模型只链接发布方官方仓库，并通过本机 OpenAI 兼容服务接入。
- 新增受控意图预览接口；否定、歧义、提示注入、越权目标和敏感内容会转为澄清，任何写操作始终只生成预览并要求用户确认。

## 数据与安全

- 数据库加法迁移 `0021` 新增会议出席、会议决议、中心组学习计划和专题、发展党员参考计划快照，以及业务会议专属字段；`0022` 增加业务附件幂等上传标识、可恢复删除、清理状态和索引。旧会议及附件保留原记录，缺失字段显示“待补充”。
- Cookie 会话的状态修改请求增加同源校验和会话级 CSRF 防护；敏感响应使用 `no-store` 并统一安全响应头。
- 党务台账的修改、导出和跨对象访问执行对象级权限检查；AI 默认不能读取发展党员、中心组发言和会议敏感材料。
- 本版不增加外部遥测。发布门禁使用本地秘密扫描、依赖审计、静态分析和针对性攻击用例，不使用 Codex Security 插件。

## 兼容性与已知边界

- 各平台安装包只有在各自构建、文件头、大小、SHA-256、静态资源闭包和安装后自检通过后才公开；本轮已冻结 Windows 三包、Linux 双格式双架构四包和 macOS 双架构 PKG，共九个制品。实际状态以 `support-matrix-1.4.5-rc.1.json` 与发布清单为准。
- Windows 安装器没有商业 Authenticode 签名，可能出现 SmartScreen 信誉提示。macOS PKG 使用 ad-hoc 签名、未使用 Developer ID 且未公证，首次打开前须核对 SHA-256，并只通过系统“隐私与安全”界面放行；不得复用旧包或全局关闭系统安全策略。
- Windows 7 已停止系统级安全维护，只建议在隔离、受控局域网使用。国产商业 Linux 与 macOS 缺少真实用户设备验收的目标继续明确标记验证边界。
- Win7 x64/x86 冻结前会使用真实 Python 3.8 导入完整应用，安装包还会在目标电脑运行健康自检；这两道门禁专门拦截“能够安装但双击无反应”的类型与路由兼容问题。
- Win7 构建还会在隔离数据目录执行从空库到 `0022` 的完整迁移链，防止历史迁移在 Python 3.8 下初始化失败。

## 升级与回滚

1. 升级前在“备份与灾备”完成一次可读取备份，并退出正在运行的 PartyOps 页面。
2. 下载与系统、包格式和 CPU 架构完全一致的安装包，核对 SHA-256 后原位安装，无需卸载旧版。
3. 数据库由 `0020` 依次增量迁移至 `0021` 和 `0022`；安装后健康检查失败时恢复二进制、配置与数据库快照。
4. 重新选择运行身份时，向导先验证旧模式可恢复，再切换服务、端口和防火墙规则；失败时不得删除原业务数据。
