# PartyOps 1.4.5-rc.4 升级与回滚

版本：`1.4.5-rc.4`；数据库迁移：`0024`；最低直接升级基线：`1.4.5-rc.2`。

## 升级前

1. 不要卸载或删除现有数据目录；关闭重复的 PartyOps 页面和进程。
2. 核对安装包平台、CPU 架构、文件长度和 SHA-256。Windows/macOS 未商业签名或公证时，只按官网说明单次放行，禁止关闭系统安全机制。
3. 确认数据盘有足够空间。升级至少需要数据库、附件和档案索引归档大小的两倍可用空间。
4. 不要直接复制正在使用的 SQLite 文件，也不要手工删除 `partyops.db-wal` 或 `partyops.db-shm`。

## 受控启动事务

1. 通过 SQLite 在线备份 API 生成一致数据库快照，同时收集受管附件和档案索引。
2. 校验备份 ZIP 边界、成员闭包、逐文件长度与 SHA-256，并对快照执行 `quick_check` 和 `integrity_check`。
3. 原子写入 `logs/upgrade-transaction.json`，状态依次为 `backup_verified`、`migrating`、`validating`、`completed`。
4. 执行 Alembic `0023 → 0024` 后，验证版本、FTS5、SQLite 最低版本、管理员不变量和业务健康端点。
5. 只有全部成功后，才用新模型登记升级前备份和升级记录。

迁移阶段强退或断电时，下次启动读取事务日志，先恢复已验证的 `0023` 快照，再重新执行完整事务。失败的半迁移数据库以 `partyops.upgrade-failed-<时间>.db` 保留用于诊断。

## 错误码

- `[UPGRADE_BACKUP_FAILED]`：升级前备份或事务日志未完成；数据库没有迁移，无需回滚。
- `[DATABASE_SCHEMA_FAILED]`：结构迁移或迁移后不变量失败；界面同时说明是否已恢复升级前快照。
- `[SQLITE_RUNTIME_FAILED]`：仅用于 SQLite 驱动加载、最低版本或 FTS5 能力不满足。
- `[DATABASE_LOCKED]`、`[DATABASE_CORRUPT]`、`[DATABASE_IO_FAILED]`、`[DATA_DIR_FULL]`：分别处理占用、完整性、读写权限/介质和空间问题，不互相混用。

## 安装后核验

- 健康接口报告 `1.4.5-rc.4`，数据库版本为 `0024`，管理员、事项、档案、附件和协同配置可读取。
- 升级前备份清单标记来源模式 `0023`，升级记录为 `completed`。
- 全新安装和 rc.2 覆盖升级都能进入今日工作台；提醒、协同、导入、导出、备份恢复和卸载保留数据回归通过。
- 安装目录与数据目录支持本机固定 D/E 盘、中文和空格路径；网络盘、移动盘、重解析点及来源不明的非空目录继续拒绝。

## 回滚

启动事务失败时由程序自动恢复数据库快照；安装事务继续恢复上一版二进制、配置与证书。若界面显示“自动回滚未完成”，不要删除或移动数据目录，复制诊断摘要和日志后停止重复安装。完整删除预检失败时只删除程序并保留数据。
