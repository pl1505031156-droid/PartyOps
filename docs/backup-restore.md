# 备份恢复与灾备切换手册

## 自动与手动备份

默认每日 18:30 创建自动备份，保留最近 14 个日备份和 8 个周备份；手动备份不自动删除。备份使用 SQLite 在线快照，包含数据库、任务材料、重要档案扫描件、归档索引、必要配置和逐文件 SHA-256 清单。只读纳管的外部原始文件夹不会整目录复制，只有已固化或已上传到重要档案的文件进入备份。

备份扩展名为 `.partyops-backup`，实际是版本化 ZIP 容器。复制或传输备份时一并保留旁路 `.sha256` 文件。

协同终端使用只读配对令牌拉取主机最新备份。首次成功后保存 `.latest.sha256`，后续主机返回 304 时显示“主机在线，灾备副本已是最新”；网络中断不会覆盖上次可用副本，恢复在线后补拉。

## 恢复前检查

1. 确认备份来自可信主机。
2. 在“系统设置 → 备份与灾备”上传校验，确认格式、版本和所有哈希通过。
3. 确认磁盘剩余空间至少为备份解压大小的 2.5 倍。
4. 通知另一位使用者停止操作。

## 恢复过程

恢复入口只允许管理员使用。系统按以下顺序执行：

1. 校验备份格式版本、模式版本和 SHA-256。
2. 自动创建“恢复前备份”。
3. 解压到数据目录内的暂存目录并拒绝越界路径。
4. 暂停数据库连接，原子切换数据库和附件。
5. 执行向前迁移并验证 SQLite/FTS5。
6. 成功后清理旧副本；失败则自动回滚旧数据库与附件。

恢复完成后重新登录，抽查用户、最近任务、终稿附件和搜索。

每次恢复前自动生成 `PartyOps-pre-restore-*.partyops-backup`。恢复过程中任何清单、哈希、空间、数据库切换或迁移错误都必须保持现有数据不变或自动切回该恢复前状态。

## 主机故障后由终端切换

1. 在终端灾备目录选择最近的 `.partyops-backup` 并核对 `.sha256`。
2. 在备用主机安装相同或更高版本 PartyOps。
3. 完成空白主机首次配置，然后使用管理员恢复入口导入备份。
4. 把备用主机绑定到原局域网地址，或通知协同终端更新 `host_url`。
5. 重新生成终端配对令牌；旧主机恢复后不得同时运行。
6. 验证双端任务更新、附件下载、SSE 和新备份，再宣布切换完成。

## 恢复演练

至少每季度在隔离机器执行一次：备份校验、完整恢复、随机附件哈希、搜索、登录、创建事项、再次备份。将演练时间、备份编号、结果和问题记录到验收表。
