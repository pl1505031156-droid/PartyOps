# PartyOps 1.3.4 发布就绪记录

最后验证：2026-08-04

## 已通过

- 后端 151 项功能测试全部通过。
- 前端 35 项组件/逻辑测试、4 项静态入口测试、TypeScript 类型检查与生产构建通过。
- amd64、ARM64 离线 wheelhouse 均通过 61 项依赖闭包检查；包含 NumPy 2.2.6、ONNX Runtime 1.22.1、Tokenizers 0.21.4。
- 设备心跳、命令轮询、目录同步和更新命令采用独立调度；更新成功后协同 Agent 自动重启。
- 更新锁支持异常中断恢复，同时保留真实升级进程的互斥保护。
- 安装器在报告成功前验证核心程序与 `partyops-updater.service`。
- 更新包校验继续执行 Ed25519 签名、版本、架构、大小、SHA-256 和路径安全检查。

## 尚未满足的正式推广门槛

- 后端覆盖率为 74.41%，低于项目 90% 门槛。
- 前端全量行/语句覆盖率为 5.12%，主要页面自动化覆盖不足。
- 当前 Windows 环境不能完成 UOS V20 amd64/ARM64 原生 `.deb`、便携包和 `.partyops-update` 构建验收。
- 尚需在真实三机环境完成双架构安装、入网、断线重连、系统内更新、回滚和连续运行验证。

## 发布判定

当前源码与 Build Kit 可用于 UOS 目标机原生构建和试装，不应标注为“已完成双架构正式推广验收”。正式分发前，必须在两种架构目标机生成对应 `.deb`，汇总为已签名 `.partyops-update`，并完成上述实机门槛。

## 回滚

- 程序升级失败：由受限更新助手安装上一版本同架构 Debian 包。
- 数据迁移或健康检查失败：恢复升级前 `.partyops-backup`，健康检查完成前保持只读恢复页。
- 更新助手损坏：使用同架构 `.deb` 做一次修复性原位升级，保留 `/var/lib/partyops`。
