# 党建智办 1.1.3 应用内更新说明

最后更新：2026-07-29

## 本次更新

- 原始文件中心先只读发现全部文件和目录，再由管理员勾选真正接入系统的文件夹；未勾选内容不提取正文、不进入全局搜索、不能预览或下载。
- 系统设置新增“已安装版本历史”，记录每次安装时间、版本号、数据库模式和更新内容。
- 主机统一管理协同电脑版本。协同电脑低于主机版本时，只能进入更新页，不能进入业务页面。
- 协同电脑更新页显示当前版本、目标版本和更新内容；用户点击“开始更新”后由本机 Agent 自动安装，成功后自动进入系统。
- 设备协同中心显示每台电脑“版本一致、等待更新、更新中、更新失败、未知版本”等状态。
- 快速新建以及新增、编辑、审批、批量处理等弹窗统一居中；小屏只滚动正文，标题和底部操作按钮始终可见。
- 数据库模式升级到 `0010`，保留原有用户、任务、附件、档案、文件索引、备份和设备证书。

正式交付文件为：

```text
partyops_1.1.3.partyops-update
partyops_1.1.3.partyops-update.sha256
党建智办-1.1.3-更新说明.txt
```

`.partyops-update` 必须同时包含 UOS V20 amd64 与 ARM64 的原生 `.deb`，并通过 Ed25519 发布签名。不要把 `PartyOps-UOS-build-kit.zip` 当作日常更新包。

## 从 1.1.2 更新到 1.1.3

这是进入“协同电脑自行确认强制更新”机制的过渡版本：

1. 在主机打开“系统设置 → 备份与灾备”，执行一次手动备份并把备份复制到另一台电脑。
2. 打开“系统设置 → 系统更新”，导入 `partyops_1.1.3.partyops-update`。
3. 等待签名、版本、双架构、磁盘空间和数据库检查全部通过。
4. **在仍运行 1.1.2 的更新页面中，这一次只选择升级主机。** 旧版编排器还不会等待终端人员确认，不能在这一步选择全部终端。
5. 主机自动备份、安装、迁移到数据库模式 `0010`、重启并健康检查。
6. 主机进入 1.1.3 后，所有低版本协同电脑再次打开“党建智办”时都会看到强制更新页。
7. 协同人员核对更新内容后点击“开始更新”。Agent 自动下载本机架构对应的安装程序、校验并安装；成功后页面自动进入系统。
8. 主机管理员在“设备协同中心”确认所有在线电脑均显示“版本一致 1.1.3”。离线电脑会保持“等待更新”，下次上线时再提示。

更新期间不会新建第二个应用、第二个图标或第二份业务数据库。

## 1.1.3 之后的日常更新

从 1.1.3 开始，管理员只需要：

1. 在主机导入下一版 `.partyops-update`；
2. 主机自动把全部有效协同电脑登记为本次更新目标；
3. 主机先完成备份、程序安装、数据库迁移和健康检查；
4. 协同电脑进入系统时显示版本和更新内容，确认后自动更新；
5. 主机版本看板持续显示未更新、更新中、已完成和失败原因。

只要协同电脑版本低于主机，它就不能调用任务、文件、档案、报告等业务接口。设备入网、登录、健康检查和更新接口仍可使用，确保能够恢复。

## 首次安装和旧版桥接

- 新电脑首次安装仍使用与架构匹配的 `partyops_1.1.3_amd64.deb` 或 `partyops_1.1.3_arm64.deb`。
- 1.0.0 没有应用内更新助手，必须最后手动原位安装一次同架构 1.1.3 `.deb`，不得先卸载。
- 1.1.1/1.1.2 已有更新助手，优先使用签名 `.partyops-update`，无需再次解压 Build Kit。
- 禁止使用 `--force-architecture` 把 amd64 包安装到 ARM64，反之亦然。

## 失败与回滚

- 更新前自动建立升级前备份并保存旧版程序包。
- 签名、哈希、架构、磁盘或数据库预检失败时不会替换当前程序。
- 主机健康检查失败时恢复旧版 Debian 包和升级前数据快照，并保持服务停止以避免继续写入。
- 终端安装中断后仍被版本门禁保护；重新打开 PartyOps 可继续更新。
- 不要删除 `/var/lib/partyops`、更新记录、升级前备份和系统日志。

故障取证：

```bash
sudo systemctl status partyops --no-pager
sudo journalctl -u partyops -n 200 --no-pager
sudo journalctl --user -u partyops-agent -n 200 --no-pager
```
